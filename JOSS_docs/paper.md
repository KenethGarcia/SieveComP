# Summary

SeisComP is a comprehensive seismological software platform designed for real-time data acquisition, automatic processing, and interactive event analysis. Many seismic monitoring networks worldwide rely heavily on it as the core of their operational processing systems. However, although the initial automatic event detection and location are complete, performing routine quality control, identifying duplicate events, and standardizing the resulting seismic catalogs often requires significant manual effort from analysts or the continuous maintenance of ad-hoc scripts.

**SieveComP** is an open-source Python package designed to automate, standardize, and accelerate the post-processing and revision of seismic catalogs generated by SeisComP. It is built to accommodate diverse technical backgrounds: beginner seismologists and network operators can leverage human-readable, declarative TOML configuration files to define complex validation rules (such as geographic bounding boxes, custom polygonal zones, depth constraints, and duplicate event detection) in just a few lines of code. Simultaneously, SieveComP provides a robust, low-level Python API that grants advanced users and researchers a way to customize, extend, and directly manipulate the validation pipelines.

Furthermore, as the use of agentic Artificial Intelligence (AI) increases in scientific workflows, SieveComP serves as a crucial, secure abstraction layer. It provides a structured framework that allows AI-driven agents to independently monitor data quality, generate visualizations, design chatbots and automate routine reporting. By restricting AI interactions to SieveComP's well-defined engine, observatories can harness the efficiency of autonomous agents while mitigating the severe risks of unconstrained AI database manipulation (i.e., granting direct access to sensitive production databases).

In this Python package, SieveComP’s core engine translates these rules into highly efficient, vectorized operations capable of processing thousands of events in seconds. It also supports database queries between different SeisComP versions and systems to provide a unified catalog view, making it a suitable tool to rapidly filter, audit, and curate high-quality seismic data.

# Statement of Need

Ensuring the long-term quality of seismic data and catalogs from large networks remains a critical challenge in seismology, especially as the volume of available events continues to grow exponentially. While platforms like SeisComP [@hanka2010seiscomp] are standard for initial real-time event detection and location, refining the resulting catalogs into a highly reliable dataset is historically a manual, non-standardized process disposed to human error and scaling bottlenecks.

Recent literature remarks the growing necessity for automated quality assurance frameworks across seismological workflows. For example, the _Scalable Seismological Pipeline for Assessment, Review, and Quality (SSPARQ)_ was recently introduced to automate the assessment of station performance, orientation trends, and waveform quality [@coelho2026ssparq]. Furthermore, foundational ecosystem tools like _ObsPy_ provide extensive libraries for general seismological data analysis and waveform manipulation [@megies2011obspy]. However, there remains a gap in the software ecosystem for tools designed specifically to audit the downstream parametric catalogs produced by SeisComP databases. Network operators currently lack robust, out-of-the-box engines focused on the rule-based validation of magnitudes, depth thresholds, custom tectonic spatial distributions, and logical deduplication.

SieveComP directly addresses this need by providing an open-source, high performance validation engine tailored exclusively for SeisComP deployments. It allows operators to apply standardized, reproducible filtering rules (via TOML configurations) to ensure that discrepancies are systematically flagged before catalog publication. By providing a secure, read-only abstraction layer, SieveComP modernizes the catalog review process for human analysts and provides a safe API boundary for next-generation AI-driven monitoring agents, reducing analyst workload and improving the fidelity of published seismicity datasets.
